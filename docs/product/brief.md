# LearnLoop — personal MVP brief

Updated November 25, 2026. Owner: Sam. First local build authorized; hosting separately approved.

**Purpose:** turn material Sam is learning into knowledge he can explain and use after a delay. Add a useful idea, understand it, practice bringing it back, see what is slipping, and return at a sensible interval. Calm, quick sessions on Android/Chrome are the priority, with a usable PC interface and one shared library/history.

**First subject:** how a data-center project moves from requirements and feasibility through design, procurement, construction, commissioning, handover and operation. Learn normal practice, dependencies, roles and how physical systems interact. A real project can illustrate the flow; individual-project/supplier intelligence is not the learning objective. Twenty-four sourced starter items cover six connected areas. They are personal draft learning material, not an industry credential or work instruction.

**Daily workflow:** Today offers a five-minute session with due recall first and up to three new items. First review the reference answer, reasoning and source context. Choose an answer, work on other ideas, then revisit the choice. Progress to a typed or aloud answer without choices. Reveal the answer, compare required ideas, and self-rate Again/Hard/Good/Easy. Recognition prepares learning; only production recall changes its schedule. See recent misses and repair confusing prompts rather than repeatedly guessing.

**Input:** capture a note/pasted passage with optional article/report link; save for later or write one prompt, a reference answer, an explanation and one to three required ideas. Keep the source title, locator, version and scope visible. Links are references rather than automatic extraction. Manual notes are unverified. Corrections preserve original revisions and history and restart learning. Ziggy can later supply reviewed content files; it is not a v1 dependency. Start with these 24, not the old spec's 120-item target.

**Experience:** Today, focused Practice, Library with source-backed item detail/corrections, Add, and Data. Quiet green palette, system fonts, large touch controls, no leaderboard, streak pressure or commercial packs. Due recall remains available offline after download, with a durable pending outbox. All acknowledged browser sessions use the same server database. Backups are versioned JSON with validated preview and explicit restore.

**As built:** local Node 24/SQLite + responsive PWA, pinned FSRS, 24-item staged learning, source links, manual capture/items, immutable corrections, conflicts, offline recall and JSON recovery. It is a locally tested slice of the shared hosted target; actual phone access is pending approved hosting. The first content expansion is draft multiple-choice checks, assessed independently from UI usability.

**Next direction:** an ASL subdomain for regular personal use and a few invited friends, improving the app while learning. A small private pilot needs real sign-in, private per-person histories, a deliberate shared-set policy, persistent hosting and off-machine recovery before launch. Exact ASL domain/subdomain and runtime are unconfirmed. No hosting, deployment, paid services, public signup, commercial content pipeline or autonomous jobs have been authorized here. Playspace readiness is not assumed.

**Success:** Sam can capture an idea, finish a short session, explain the important connections a week later and recover his library. Measure delayed free recall on parallel unfamiliar scenarios against time-matched note review; app completion and choice accuracy alone are insufficient evidence. See `docs/validation-plan.md`.
